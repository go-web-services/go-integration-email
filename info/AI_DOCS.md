# AI Documentation: Email Service Development Guide

This document provides comprehensive guidance for AI assistants to help developers create new email types in the GLD Integration Email Service.

## System Overview

This is a **Go-based email service** that manages different email templates for the Remedy platform. The service uses:

- **Go** backend with Gin framework
- **HTML/Text templates** for email content
- **Template mapping system** for email type routing
- **Swagger documentation** generation
- **Client SDK** for type definitions

## Required User Information

Before creating any new email type, **ALWAYS ask the user for these details**:

1. **Folder name** (e.g., `query-contribution-new`)
2. **Email content/template** (text or description)
3. **Email parameters** (template variables like `{{.Username}}`, `{{.Title}}`)
4. **Email type constant name** (e.g., `QueryContributionNew`)
5. **Subject line** for the email

**Never proceed without this information.**

## Step-by-Step Email Creation Process

### Step 1: Create Template Directory

```bash
mkdir -p internal/templates/gld/query-db/{folder-name}
```

**Location**: `internal/templates/gld/query-db/`
**Pattern**: Use kebab-case for folder names (e.g., `query-contribution-status-change`)

### Step 2: Create Template Files

Create exactly **3 files** in the new folder:

#### 2.1 HTML Template (`body.html`)

**File**: `internal/templates/gld/query-db/{folder-name}/body.html`

**Template Structure**:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="color-scheme" content="light dark" />
    <meta name="supported-color-schemes" content="light dark" />
    <title>{Email Title}</title>
    <style>
      /* COPY EXACT CSS FROM EXISTING TEMPLATES */
    </style>
  </head>
  <body
    style="margin: 0; padding: 0; color: #222126; font-family: Verdana, Arial, sans-serif; background-color: #ffffff;"
  >
    <!-- COPY EXACT HTML STRUCTURE FROM EXISTING TEMPLATES -->
    <!-- Main content goes in the Description section -->
    <!-- Use {{.ParameterName}} for template variables -->
  </body>
</html>
```

**Important**:

- **Always copy CSS and HTML structure** from existing templates
- Use **secondary button** style for notification emails (outlined button)
- Use **primary button** style for action emails (solid background)
- Include all standard sections: Header, Content, Button, Footer, Social

#### 2.2 Text Template (`body.txt`)

**File**: `internal/templates/gld/query-db/{folder-name}/body.txt`

**Template Structure**:

```text
{Email content with {{.ParameterName}} variables}

You can view the contribution thread at: {{.ThreadLink}}

Best regards,
The Remedy Team

This message is automatically generated by Remedy. You've received this message because this email address is associated with your Remedy account.

© Remedy 2025, All rights reserved
```

#### 2.3 Subject Template (`subject.txt`)

**File**: `internal/templates/gld/query-db/{folder-name}/subject.txt`

**Content**: Single line with the email subject (e.g., "Query status updated")

### Step 3: Add Email Type Constant

**File**: `pkg/client/constants/constants.go`

**Action**: Add new constant to the existing `var` block:

```go
var (
    QueryContributionApprove      types.EmailType = "QueryContributionApprove"
    QueryContributionReject       types.EmailType = "QueryContributionReject"
    QueryContributionOutdate      types.EmailType = "QueryContributionOutdate"
    QueryContributionNew          types.EmailType = "QueryContributionNew"
    QueryContributionStatusChange types.EmailType = "QueryContributionStatusChange"
    // ADD NEW CONSTANT HERE
    NewEmailType                  types.EmailType = "NewEmailType"
)
```

### Step 4: Update Email Mappings

**File**: `internal/mappings/email_mapping.go`

**Action**: Add new mapping to `EmailTypeMapping`:

```go
var EmailTypeMapping = map[clientTypes.EmailType]EmailInfo{
    // ... existing mappings ...
    clientConsts.NewEmailType: {
        HTMLTemplateFileName: buildTemplatePath("gld/query-db/{folder-name}/body.html"),
        TextTemplateFileName: buildTemplatePath("gld/query-db/{folder-name}/body.txt"),
        SubjectFileName:      buildTemplatePath("gld/query-db/{folder-name}/subject.txt"),
    },
}
```

**File**: `info/EMAILS_DESCRIPTION.md`

### Step 6: Create/Update DTOs

**Files**: Choose the appropriate DTO file based on email type:

- `pkg/client/dto/query_db_dto.go` - For Query DB related emails
- `pkg/client/dto/website_dto.go` - For Hexens website related emails
- `pkg/client/dto/dto.go` - Contains shared base DTOs (don't modify unless adding new base types)

**Purpose**: DTOs define the expected parameters for external services consuming the email API.

**Action**: Add input DTO and parameters struct for the new email type in the appropriate file:

```go
type NewEmailTypeInputDTO struct {
	BaseSendEmailDTO
	Params NewEmailTypeParams `json:"params" binding:"required"`
}

type NewEmailTypeParams struct {
	Username   string `json:"username" binding:"required"`
	Title      string `json:"title" binding:"required"`
	ThreadLink string `json:"threadLink" binding:"required"`
	// Add all template variables used in your email templates
}
```

**Important Notes**:

- **Always include all template variables** used in HTML/text templates
- Use `binding:"required"` for mandatory parameters
- Follow the naming pattern: `{EmailType}InputDTO` and `{EmailType}Params`
- **Update existing DTOs** if you modify template parameters in existing emails

**Common Parameters**:

- `Username` - Recipient's username
- `Title` - Query/contribution title
- `ThreadLink` - Link to contribution thread
- `ActorUsername` - Person who performed the action
- `NewStatus` - Updated status value
- `Reason` - Reason for rejection/action

## Email Types and Button Styles

### Primary Button (Solid)

**Use for**: Action emails (approve, main CTAs)
**Style**: Dark background (#222126), white text (#FFFFFF)
**Class**: `primary-button`

### Secondary Button (Outlined)

**Use for**: Notification emails (status updates, info)
**Style**: Transparent background, dark border and text (#222126)
**Class**: `secondary-button`

## Template Variables Patterns

Common template variables used across emails:

- `{{.Username}}` - Recipient's username
- `{{.Title}}` - Name of the query
- `{{.ThreadLink}}` - Link to contribution thread
- `{{.NewStatus}}` - Updated status value
- `{{.ActorUsername}}` - Person who made the change

## Common Mistakes to Avoid

1. **Don't create files without asking for required information**
2. **Don't modify CSS/HTML structure** - always copy from existing templates
3. **Don't forget to update all 5 locations**: templates, constants, mappings, DTOs, docs
4. **Don't use incorrect button styles** - check email type for appropriate style

3. **QueryContributionOutdate** - Outdated query notification (primary button)

## Development Workflow

1. **Gather requirements** from user
2. **Create templates** (copy structure from existing)
3. **Add constants** and mappings
4. **Update documentation**
5. **Create/update DTOs** for external API consumption
6. **Test with curl** command

## Template Customization Guidelines

- **Always preserve** the email layout structure
- **Customize only** the title, description, and button text
- **Use consistent** spacing and typography
- **Include all required** template variables
- **Test both** HTML and text versions

This guide ensures consistent email creation and helps maintain the service's architecture and design patterns.
